# Кинодневник — заметки для работы над кодом

Личный дневник фильмов, сериалов, мультфильмов и аниме. Сайт: https://mykyta20.github.io/kinodnevnik/ (GitHub Pages из ветки `main`, обновляется примерно за минуту после пуша). Владелец пишет по-русски и не программист: объяснять просто, по шагам, без жаргона; в итоге — что изменилось на сайте и что ему нужно сделать (обычно ничего).

## Главные правила
- **Записей в репозитории нет и не должно быть.** Они лежат в личной Google-таблице владельца.
- **Код Apps Script (`Code.gs`) не менять.** Он вшит в `index.html` как `<script id="code-gs">` только для инструкции по установке; настоящая копия развёрнута у владельца, и переразвёртывать её он не хочет. Всё новое делается на стороне сайта через существующие действия `getAll`, `saveItems`, `deleteItems`, `replaceAll`.
- **Владелец не работает с таблицей и Apps Script напрямую.** Всё, что нужно ввести (ключи, настройки), вводится на сайте.
- Дневник работает онлайн, в основном на Mac. Мобильная версия — низкий приоритет.
- Перед пушем в `main` — тесты (см. ниже). Настоящую таблицу владельца в тестах не трогать.

## Устройство
- Весь сайт — один файл `index.html`: шрифты (строка с `@font-face` в base64, ~200 КБ, не трогать), CSS (`#app-css`), Code.gs (`#code-gs`), приложение (`#app-js`, одна IIFE без сборки). Плюс `manifest.webmanifest` и иконки.
- **Хранилище** (`Store`): в режиме Google сайт шлёт `POST` с `{key, action, arg}` на адрес веб-приложения Apps Script. Адрес и ключ хранятся в `localStorage` (`kinodnevnik:remote`), на новое устройство переносятся «ссылкой подключения» из раздела «Данные». Сохранение пакетное с задержкой ~1 с; при ошибке — повтор каждые 6 с. Ответ без поля `data` считается ошибкой (Google иногда отвечает «пустышкой» как на GET).
- **Служебная запись** `id: "__settings"` (`cat: "settings"`, поле `cfg`) лежит в той же таблице; сайт вынимает её при загрузке (`takeCfg`) и прячет из списков, сохраняет через `saveItems`, переносит при `replaceAll`. Сейчас там `cfg.tmdb` — ключ TMDB владельца.
- **Тайтл** (основные поля): `id`, `cat` (`film`, `series`, `cartoon`, `toon` мультсериал, `anime`, `animefilm`), `title`, `orig`, `year` (у сериалов «2011–…» или «2003–2019»), `status` (`done`, `watching`, `paused`, `dropped`, `planned`), `rating` 1–10, `verdict`, `pros`, `cons`, `notes`, `dates` (ISO), `dub` (озвучка), `progress`, `fav`, `rewatch`, `rec`, `tags`, `img` (постер), `ext` (`imdb`, `kp` — вписываются вручную; `tmdb`, `shiki` — оценки баз при добавлении). У аниме: `mal` (номер MyAnimeList = Shikimori), `aod` (средняя оценка аниме-баз, июль 2026), `slabel`, `franchise`, `parts` — сезоны/фильмы (`label`, `title`, `kind` tv/film/ova, `year`, `status`, `rating`, `dates`, `mal`, `img`, `orig`, `dub`, `progress`). Статус и даты аниме с частями считаются из частей (`syncParts`). У фильмов из TMDB: `tmdb` («movie/123» или «tv/456»), `imdb` («tt…»).
- Около 500 тайтлов из истории HDrezka (2020–2026). У всех 118 аниме есть `mal` и постер с cdn.myanimelist.net; у фильмов и сериалов постеров пока нет.

## Внешние базы (из браузера, без своего сервера)
- **TMDB** `https://api.themoviedb.org/3`, `language=ru-RU`, ключ из `S.cfg.tmdb` (32 символа идут параметром `api_key`, длинный токен — заголовком `Bearer`). Постеры `https://image.tmdb.org/t/p/w342…`. CORS открыт. Обязательная пометка про TMDB есть в «Данные» → «Откуда данные».
- **Shikimori** GraphQL `https://shikimori.io/api/graphql` (POST, CORS открыт, без ключа, лимит ~5 запросов/с). Старый домен shikimori.one из браузера не отвечает. Поля: `animes(search:, ids:, limit:)` → `id malId name russian english kind score status airedOn{year} releasedOn{year} franchise poster{main2xUrl mainUrl previewUrl} related{relationKind anime{…}}`.
- Jikan (api.jikan.moe) из браузера недоступен.

## Дизайн «Кинозал»
Тёплая тёмная тема по умолчанию (фон `#0F0D0C`, янтарный акцент `#F0A640`), светлая «Дневной сеанс». Цвета задаются переменными в `:root` (и для светлой темы в двух местах: `prefers-color-scheme` и `[data-theme="light"]`). Шрифты: заголовки Literata, текст Golos Text. Цвета разделов: фильмы `--c-film` (красный), сериалы `--c-series` (бирюзовый), мультфильмы `--c-cartoon` (салатовый), аниме `--c-anime` (фиолетовый). Оценки — «лампочки» `.badge.rvN`. В карточке заложена переменная `--tint` для подсветки цветом постера.

## Тесты
`tests/` — Playwright-стенд: сайт открывается по адресу GitHub Pages, а Google-таблица (поведение как у Code.gs), TMDB, Shikimori и картинки подменены (`tests/harness.js`). Запуск из папки `tests`: `node t1.js && node t2.js && node t3.js` (нужен Playwright с Chromium). Скриншоты складываются в `tests/shots/` (в git не идут). Сейчас 71 проверка: умное добавление, сезоны аниме, ключ TMDB, сбои баз, телефон, светлая тема, «пустые» ответы Google.

## План
1. **Постеры для уже записанных тайтлов** (следующий шаг). Кнопка в «Данных»: для фильмов, сериалов и мультфильмов без `img` искать в TMDB по `orig`/`title` + году, уверенные совпадения сохранять сами (`img`, `tmdb`, `imdb`), спорные показывать владельцу на подтверждение карточками с вариантами. Сохранять пачками через `saveItems`, учитывать лимиты TMDB, показывать прогресс, можно прервать и продолжить. У аниме постеры уже есть. Заодно подсветка карточки цветом постера (`--tint`; картинки TMDB отдаются с CORS). Постер можно показывать и в строках списка. Оценка IMDb через OMDb (второй бесплатный ключ) — по желанию владельца.
2. Подстраховка: в Google-таблицах есть история версий; плюс кнопка «Скачать резервную копию» на сайте (уже есть).
3. Режим «быстро оценить»: карточки по одной.
4. «Итоги года» в виде финальных титров.
5. Мобильная версия как приложение (нижняя панель, свайпы) — низкий приоритет.
